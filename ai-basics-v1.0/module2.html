Why this matters

An agent is an AI with a goal and a loop. You say what you want, and it decides the steps. A chatbot answers. An agent gets things done.

It adapts. When 7:00 was full, the agent didn’t give up. What it observed changed its next move.

Every loop adds to the chat history. Each thought, action and result gets added to the conversation, so long jobs use more tokens, cost more and fill up the context window.

But who actually does the “Act” part? The AI model only writes text. Tools turn that text into real actions.

Step 2: Who actually runs the tool?

The AI can’t press buttons or call a weather service. It can only write text. So how does a tool get used? It starts with a list. Before you type anything, the AI is given a list of tools that are available. The list sits at the top of what the AI reads, next to the system message. Each tool says what it does and what information it needs. Here is one entry from that list:

Why this matters

Tools turn words into actions. The AI asks, and something else does the work. That is how an agent can search the web, check the weather and delete files.

The right tool beats a guess. For exact maths or live facts, a tool gives a real answer. Without it, the AI gives its best guess.

The AI has a list of available tools. The list says what each tool does and what information it needs. The AI reads this list every time, so it takes up room in the context window and uses tokens, just like the system message.

Results go into the chat history. Each tool result is added to the conversation, so the more tools an agent uses, the longer the history grows.

Why this matters

The harness is everything except the AI. It runs the loop, runs the tools, keeps the chat history and decides what the AI gets to read.

Same AI, different harness. A homework helper and a coding assistant can use the same AI model. But, they behave differently because their harnesses give the AI different tools and different rules.

Safety lives in the harness. The AI can ask for anything, but the harness decides what actually runs.

MCP

Imagine you ask an agent to write an essay and then email it to your Gmail address. The AI can write the essay, because that’s just text. But it can’t send an email by itself. It needs a tool. Where does the tool come from?

Step 1: Two ways to get the tool

Pick a way above.

MCP stands for Model Context Protocol. A protocol is an agreed set of rules, like a common language. An MCP server is where a service makes its tools available. A harness can connect to an MCP server only if it follows the connection rules. When a connection is made, the harness can access the tools that are provided by that MCP Server.

Step 2: Connect some servers

Each MCP server shares a set of tools. When you connect one, the harness asks it what it can do. The server replies with its tools, and the harness adds them to the tool list the AI reads. Connect some servers and watch the number of available tools increase.

More servers means more reach, but every tool on the list takes up room in the context window. The numbers are made up, and the window is tiny so you can see it fill.

Why this matters

Reuse instead of rebuild. Building your own tool takes real work. With MCP, someone else has already built the tool and keeps it working.

More reach. An agent can use tools that live on other computers, like Gmail, a calendar, a company’s database or a weather service.

The AI doesn’t know about MCP. It only sees a tool list. The harness handles the connection, and the list simply gets longer.

Only connect servers you trust. An MCP server is someone else’s software, and your agent will use it with your account info.

Skills

Skills show agents how to do a job well. Imagine a student wanted an agent to write a lab report the way the teacher likes it: the right sections, the right style, the right table layout. The AI doesn’t know the teacher’s rules. How does that student show the agent what to do step-by-step?

What is a skill?

A skill is a folder of instructions that shows an AI how to do one specific task. Every skill folder has a file called SKILL.md, which starts with a short name and description, followed by the full instructions. The folder can also contain other files.

Like tools, the available skills are listed in the system message, but only by name and description. When you ask the AI to do something, like write a lab report, the AI sees that the “lab-report” skill fits this request. It then reads the instructions that are in that skill folder.

Step 2: A skill you can read

Here is a real SKILL.md file. It belongs to a very simple skill called joke-teller. Notice the two parts: the name and description at the top, then the instructions below.

joke-teller/SKILL.md
Always loaded: name and description
--- name: joke-teller description: Tells jokes. Use this skill when the user asks for a joke, something funny, or wants to be entertained. ---
Loaded only when the skill is used: the instructions
# Joke Teller When this skill is active, respond with a short, clean, family-friendly joke. ## Guidelines - Always deliver the joke in classic setup/punchline format - Keep it short and snappy - After the joke, ask the user if they want to hear another one

Now try it. Ask for a joke and watch the agent find the skill, load the instructions and follow them.

Press “Tell me a joke” to start.

Compare the AI's response to the instructions given in the SKILL.md file. You'll see that the AI followed the instructions when responding - the AI told a short joke in setup/punchline format, then asked if you want another one.

Why this matters

Skills save room in the context window. Only a short name and description are always loaded. The full instructions arrive when the AI needs them, so an agent can have lots of skills without filling its window.

The description matters. The AI picks a skill by reading its description, just like it picks a tool from the tool list.

Anyone can write a skill. It’s just a folder with instructions.

Only use skills you trust. A skill that's written by someone else can include malicious instructions that can cause your agent to do things you didn't expect e.g. delete your files.
